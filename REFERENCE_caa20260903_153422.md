# test-hugo — Configuration Reference

Boilerplate: **Hugo + [PaperMod](https://github.com/adityatelange/hugo-PaperMod)**, deployed to
GitHub Pages. Generated 2026-09-03 15:34:22 by inspecting the theme source at PaperMod master
(`d376885`, 2026-08-02).

This document splits the surface into **what you can change**, **what you can change but should
not**, and **what you cannot change without overriding theme templates**.

---

## 0. Read this first: which theme version you are running

`.github/workflows/pages.yml` runs `hugo mod get -u $THEME_URL`. The `-u` means **the theme floats to the
latest master on every build.** The commit pinned in `go.mod` is *ignored* at build time.

Consequences:

- New PaperMod params become available without any action from you.
- A breaking upstream change lands in your site without warning.
- Snippets from the web may target an older theme. Notable trap: the dark-mode CSS selector is
  `:root[data-theme="dark"]` on master, but was `.dark` until early 2025. Snippets written for
  `.dark` silently do nothing.

To pin instead, drop `-u` from the workflow's `Fetch theme` step and commit an exact version in
`go.mod`.

## 1. Cannot be changed in config — no param exists

These require overriding theme files (see §5) or CSS (see §2).

| Thing | Why | Workaround |
|---|---|---|
| **Fonts** | PaperMod has no font param. One `font-family` declaration exists, in `assets/css/core/reset.css:27` (a system-font stack). | Override `body { font-family: ... }` in `assets/css/extended/custom.css`. A webfont also needs `@font-face` or a `<link>` via an `extend_head.html` override. |
| **Colours** | Not params — CSS custom properties. | See §2. |
| **Layout geometry** (content width, header height, gaps, corner radius) | CSS variables only. | See §2. |
| **Nav/menu markup** | Built from `[[languages.en.menu.main]]`; structure is fixed. | Override `layouts/partials/header.html`. |
| **Post card layout** | Fixed template. | Override `layouts/_default/list.html`. |
| **Footer markup** | Only text and copyright are params. | Override `layouts/partials/footer.html`. |

## 2. Colour scheme and layout — CSS only

PaperMod concatenates `assets/css/extended/*.css` **after** its own core CSS, so
`assets/css/extended/custom.css` (already in this repo) is the supported override point. No build
config needed; add more `.css` files to that directory and they are all included.

Full set of theme variables — redefine any subset:

```css
:root {
    /* colours — light */
    --theme: rgb(255, 255, 255);      /* page background */
    --entry: rgb(255, 255, 255);      /* card / post background */
    --primary: rgb(30, 30, 30);       /* headings, strong text */
    --secondary: rgb(108, 108, 108);  /* meta, muted text */
    --tertiary: rgb(214, 214, 214);   /* hover fills */
    --content: rgb(31, 31, 31);       /* body copy */
    --code-block-bg: rgb(28, 29, 33);
    --code-bg: rgb(245, 245, 245);
    --border: rgb(238, 238, 238);

    /* layout geometry */
    --gap: 24px;
    --content-gap: 20px;
    --nav-width: 1024px;
    --main-width: 720px;
    --header-height: 60px;
    --footer-height: 60px;
    --radius: 8px;
}

:root[data-theme="dark"] {
    --theme: rgb(29, 30, 32);
    --entry: rgb(46, 46, 51);
    --primary: rgb(218, 218, 219);
    --secondary: rgb(155, 156, 157);
    --tertiary: rgb(65, 66, 68);
    --content: rgb(196, 196, 197);
    --code-block-bg: rgb(46, 46, 51);
    --code-bg: rgb(55, 56, 62);
    --border: rgb(51, 51, 51);
}
```

Syntax highlighting is Hugo's Chroma, not the theme. `[markup.highlight] noClasses = false`
emits CSS classes, so a Chroma stylesheet can be generated and dropped into
`assets/css/extended/`:

```shell
hugo gen chromastyles --style=github > assets/css/extended/chroma.css
```

## 4. Do NOT change — deployment-critical

### `baseURL` is injected by CI. Do not hardcode a site URL.

`.github/workflows/pages.yml` builds with `hugo --minify --baseURL "<base_url>/"`, where `base_url`
is the `actions/configure-pages` step output — the real deployed Pages URL, resolved at build time.
It is GitHub's equivalent of GitLab's `$CI_PAGES_URL`. The flag overrides `config.toml`, so one
setup handles the project subpath URL (`https://irboi746.github.io/research_diary/`), repo and
account renames, and a custom domain added later in repo settings, with no edits.

`config.toml` has `baseURL = "/"`, which now only affects **local** builds — it makes
`hugo server` serve at `http://localhost:1313/` rather than under a subpath.

Things that do **not** work, and why — Hugo defines `baseURL` as *"The absolute URL of your
published site including the protocol, host, path, and a trailing slash"*:

| Attempt | Result |
|---|---|
| `relativeURLs = true` | Hugo docs: *"Do not enable this option unless you are creating a serverless site, navigable via the file system"* — a brute-force search/replace that can corrupt content. Verified here: HTML links go relative, but RSS `<link>` and `og:url` stay non-absolute, breaking feed readers and link previews. |
| `baseURL = "/"` for production | Same metadata problem, and only works at a domain root. |
| Hardcoding the Pages URL | Breaks on a repo or account rename, or a custom domain added later. |

Caveats to be aware of:

- A local `hugo` build **without** `--baseURL` emits `/` as canonical and in RSS links. Fine for
  previewing; pass `--baseURL` by hand if building outside CI for real.
- `hugo server` prints its address as `//localhost:1313/` (scheme-less value). Cosmetic only.
- `hugo server` overrides only the **scheme and host** of `baseURL`, *not the path*. A subpath
  `baseURL` therefore makes `http://localhost:1313/` return 404.
- `base_url` carries **no trailing slash**, so the workflow appends one in the `--baseURL` argument.
- `base_url` is **empty** when `configure-pages` has not run. The workflow skips that step off the
  default branch — it calls the Pages API and is unreliable in pull-request contexts — so the build
  step falls back to `http://localhost:1313`. Pull-request builds therefore validate templates and
  config without touching Pages, but do not exercise the production subpath.

### Do not re-add these — they do nothing

| Setting | Status |
|---|---|
| `[params.assets] disableHLJS` | **Dead.** No reference anywhere in the theme. PaperMod dropped highlight.js; highlighting is Chroma now. Removed from this repo. |
| `pygmentsUseClasses` | Legacy Hugo alias for `[markup.highlight] noClasses`. Was set redundantly alongside it. Removed from this repo. |
| `assets.disableScrollBarStyle` | Existed in Jan 2025 PaperMod, removed on master. Since this repo floats to master, it is a no-op. |

### Inert in this repo — set, but nothing consumes it

`ShowAllPagesInArchive = true` is set in `config.toml`, but PaperMod's archive view only renders
for a page that opts into the layout. There is no such page here, so `/archives/` returns 404 and
the param does nothing. To activate it, add:

```yaml
---
title: "Archive"
layout: "archives"
url: "/archives/"
---
```

as `content/archives.md`, and add a matching `[[languages.en.menu.main]]` entry.

## 5. Overriding theme templates

Hugo resolves a file in the project's `layouts/` ahead of the theme's. Copy the file from the
theme module and edit the copy. PaperMod also provides two extension hooks that survive theme
updates and are preferable to a full override:

- `layouts/partials/extend_head.html` — injected into `<head>`
- `layouts/partials/extend_footer.html` — injected before `</body>`

The theme source is not vendored in this repo. To read it:

```shell
git clone https://github.com/adityatelange/hugo-PaperMod.git /tmp/papermod
```

Note that on master the theme uses Hugo's newer layout structure (`layouts/_partials/`,
`layouts/list.html`), which requires Hugo ≥ 0.146.

## 6. Repo layout

| Path | Purpose | Safe to edit |
|---|---|---|
| `config.toml` | All site config | Yes — except `baseURL`, see §4 |
| `content/` | Pages and posts | Yes |
| `assets/css/extended/custom.css` | Custom CSS override point | Yes |
| `static/` | Copied verbatim to site root (`favicon.ico`) | Yes |

| `themes/` | Empty (`.gitkeep`) — theme comes from the module, not here | Leave |

## 7. Verifying a change

Local preview:

```shell
hugo mod get -u github.com/adityatelange/hugo-PaperMod
hugo server
```

Simulate the real CI build against the production URL. CI pins its own Hugo version
(`HUGO_VERSION` in the workflow), so this image approximates CI rather than matching it exactly:

```shell
docker run --rm -e PAGES_URL="https://irboi746.github.io/research_diary" \
  -v "$PWD":/src -w /src hugomods/hugo:exts sh -c '
    hugo mod get -u github.com/adityatelange/hugo-PaperMod
    hugo --minify --baseURL "$PAGES_URL/" -d /tmp/ci
    grep -o "<link rel=canonical href=[^>]*>" /tmp/ci/about/index.html
    grep -o "<link>[^<]*</link>" /tmp/ci/index.xml | head -1
    grep -o "href=[^ >]*stylesheet[^ >]*" /tmp/ci/index.html | head -1'
git checkout -- go.mod go.sum
```

Expect no `WARN`/`ERROR`, canonical and RSS `<link>` absolute on the given host, and the
stylesheet path prefixed to match.
